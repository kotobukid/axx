# 環境設定の実験から得られた知見

このドキュメントは、本プロジェクトのGitログから抽出された環境設定および開発上の知見をまとめたものです。

## 1. バックエンド (Rust / Axum)
- **静的ファイルの配信とフロントエンド連携**:
  - `Axum` で `Vite` のビルド成果物（`index.html` や資産ファイル）を配信するように設定。
  - フロントエンドを別のフレームワーク（Vite等）に任せる場合、Axum側で直接 `Html` 関数を使ってHTMLを生成する必要はない。
- **APIのモジュール化**:
  - `/api` 以下のエンドポイントを別モジュール（`api.rs`）に切り出すことで、コードの整理とDBモック的な動作の切り分けが可能。
- **非同期トレイトと実装**:
  - DB操作のレポジトリ（`TodoRepository`）を非同期対応（`async-trait`）にする際、トレイト境界やライフタイムの扱いに注意が必要。
  - `todo!()` マクロを活用し、未実装のメソッドをプレースホルダとして残しつつコンパイルを通す手法が有効。
- **ロギング**:
  - `tracing` ライブラリを使用し、`RUST_LOG=debug cargo run` のように環境変数でログレベルを制御。

## 2. フロントエンド (Vue.js / Vite / TypeScript)
- **Viteとの連携**:
  - プロキシ設定を適切に行うことで、開発時のCORS問題を回避。
  - HTTPリクエストの送信先（APIエンドポイント）を `.env` ファイルに切り出し、ハードコーディングを排除。
- **TypeScriptの型チェック**:
  - 依存関係の更新（`npm-check-updates` 等）により、突然 `tsc` のエラーチェックが厳格化することがある。特にライブラリの型定義変更に注意。
  - `App.vue` のインポート時の型エラー回避など、Vue特有の型定義調整が必要なケースがある。

## 3. インフラ・環境構築 (Vagrant / ネットワーク)
- **設定の動的化とハードコーディング排除**:
  - `Vagrantfile` やフロントエンドのコードからIPアドレスのハードコーディングを排除し、設定ファイル（`yaml` や `toml`）から読み込む形式に変更。
- **Vagrantとネットワーク**:
  - `private_network` の設定を別ファイル（`network-config.sample.yaml` 等）に切り出し、環境に依存する設定を分離。
  - `vagrant ssh-config` を実行するディレクトリ位置に依存する自動生成スクリプトなどの相対パス調整が必要になる場合がある。
- **デプロイ設定**:
  - `.idea/deployment.xml` などのIDE設定ファイルをPythonスクリプト等で自動生成し、開発環境間での同期を容易にする試みが行われた。

## 4. 依存関係管理とセキュリティ
- **npm audit / npm-check-updates**:
  - 定期的なパッケージ更新（`npm audit fix`）によりセキュリティ警告に対応。
  - ただし、一括更新によりビルドが通らなくなるリスク（破壊的変更）があるため、更新後の動作確認が不可欠。

## 5. 開発Tips
- **Makefileの活用**:
  - 複雑なビルド手順や環境構築コマンドを `Makefile` にまとめることで、作業の再現性を高める。
- **ディレクトリ構成の変更**:
  - プロジェクトが成長する過程で、バックエンド（`myaxum`）とフロントエンド（`vite-project`）を並列に配置し、各々の責務を明確に分ける構成が採用された。
- **コミットの粒度**:
  - ファイルの移動時には、変更と移動を分けるなど、Git履歴の追跡性を考慮したコミットが推奨される。
