# Cargo Clippy の運用ガイドライン

このドキュメントでは、Rust の静的解析ツールである `clippy` を「最大限に活用」し、コード品質を維持・向上させるためのオプションの意図と運用方法についてまとめます。

## 1. 基本的な一括修正コマンド
プロジェクトのコードを一挙に「いい感じ」にするための標準的なコマンドは以下の通りです。

```bash
cargo clippy --fix --allow-dirty -- -W clippy::all -W clippy::pedantic -W clippy::nursery -W clippy::cargo
```

### オプションの意図
*   `--fix`: 自動修正可能な警告をソースコードに直接適用します。
*   `--allow-dirty`: Git 等で未コミットの変更があっても、構わずファイルを書き換えを許可します。
*   `--`: これ以降の引数が、内部で実行される `clippy` 本体（lint エンジン）に渡されることを示します。

---

## 2. 厳格さを制御するフラグ（-W と -D）

Clippy において、特定のルール（lint）に対してどの程度の厳格さで臨むかを決定するのが `-W` と `-D` です。

| フラグ | 意味 | 考え方（厳格さ） | 挙動 |
| :--- | :--- | :--- | :--- |
| **`-W`** | **Warn** | **「推奨・助言」** | 違反があっても警告として表示されるだけで、コンパイルや CI は成功します。 |
| **`-D`** | **Deny** | **「強制・拒絶」** | 違反を「エラー」として扱います。違反が一つでもあるとビルドが失敗するため、CI での利用に適しています。 |

### `-D clippy::all` の意図
`cargo clippy -- -D clippy::all` とした場合、**「標準的な推奨ルールをプロジェクトの絶対的な基準（エラー扱い）にする」**という強い意思表示になります。
`--fix` と組み合わせることで、「機械的に直せるものは一切の妥協なく一括修正し、直せないものだけを人間が確認する」という効率的なクリーンアップが可能になります。

---

## 3. Lint グループの使い分け

Clippy には数百のルールがありますが、それらは「グループ」として管理されています。

*   **`clippy::all`**: 標準的なおすすめ設定。通常、これに従うことが Rust コミュニティのベストプラクティスです。
*   **`clippy::pedantic`**: 「学者ぶった」ルール。型変換や関数の複雑さなど、より厳格で細かい指摘を行います。
*   **`clippy::nursery`**: 開発中の新しいルール。将来的に `all` に入る可能性がある、実験的な改善提案です。
*   **`clippy::cargo`**: `Cargo.toml` の記述に関するルール。

---

## 4. 推奨される運用フロー

「最大限に権利を移譲する（自動修正に任せる）」精神を持ちつつ、安全に運用するためのステップです。

1.  **一括適用（開発初期やリファクタリング時）**
    `--fix` を使って、Clippy に任せられる修正を一気に適用します。
    ```bash
    cargo clippy --fix --allow-dirty -- -W clippy::pedantic
    ```

2.  **常時適用（CI やチーム開発）**
    プロジェクトの `src/main.rs` や `src/lib.rs` の冒頭に以下を記述し、チーム全員が同じ基準でコードを書くようにします。
    ```rust
    #![warn(clippy::pedantic, clippy::nursery)]
    ```

3.  **人間による最終確認**
    自動修正は非常に優秀ですが、意図した設計を崩す可能性もゼロではありません。
    `git diff` で変更点を確認し、`cargo test` で挙動が変わっていないことを確認するのが鉄則です。
    「最終的なコードの責任者は人間である」という前提で、Clippy の提案を吟味しながら受け入れましょう。
